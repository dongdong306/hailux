Execute PowerShell commands and return the output

The current OS is Windows, commands are executed using PowerShell. All commands run in the current working directory by default. To run a command in another directory, use the workdir parameter instead of using cd in the command.

This tool is for terminal operations (such as git, cargo, npm, etc.), not for file operations (reading, writing, editing, searching) — please use dedicated tools.

Before executing a command, follow these steps:

1. Directory verification:
   - If the command will create new directories or files, first use the read tool to verify the parent directory exists and is in the correct location
   - For example, before running "mkdir foo/bar", check that "foo" exists

2. Path quoting:
   - Always use double quotes to reference file paths containing spaces
   - Correct: mkdir "C:\Users\name\My Documents"
   - Wrong: mkdir C:\Users\name\My Documents (will fail)

3. Command execution:
   - After ensuring proper quoting, execute the command and capture the output

IMPORTANT — Prefer dedicated tools over PowerShell cmdlets or aliases for file operations. Avoid using: ls, dir, Get-ChildItem, Get-Content, cat, type, Set-Content, Out-File, Select-String, Write-Output. Use the dedicated tools instead:
    - List directory / find files: use glob (avoid ls, dir, Get-ChildItem — including -Recurse, PowerShell's equivalent of find)
    - Content search: use the grep tool (avoid Select-String)
    - Read file: use read (avoid Get-Content, cat, or type)
    - Edit file: use edit (avoid string replacement scripts)
    - Write file: use write (avoid Set-Content or Out-File)
    - Output text to the user: output directly (avoid Write-Output)
Using Write-Output/echo for terminal purposes (e.g. inspecting a variable or $LASTEXITCODE) is fine — the guidance only covers file writes and communicating with the user.

Usage notes:
  - When issuing multiple commands:
    - If commands are independent and can run in parallel, call the Bash tool multiple times in a single message. For example, you can call the Bash tool twice in parallel to run git status and git diff.
    - Use ; only when you need to run commands sequentially and don't care if earlier commands fail
    - Do not use newlines to separate commands (newlines can be used within quoted strings)
    - Avoid using cd to change directories; use the workdir parameter instead
     - You can set a command timeout via the timeout parameter (in seconds). After timeout, the process will be terminated and a timeout message will be returned

# Git Operations

Only create commits or PRs when the user requests them. If unsure, ask first.

Safety protocol:
- Never update git config, never run destructive commands (push --force, hard reset, etc.) unless explicitly requested by the user
- Do not skip hooks (--no-verify), do not force push to main/master
- Do not use git commands with the -i flag (requires interactive input)
- Avoid git commit --amend; if a commit fails or has been pushed, create a new commit after fixing
- Do not commit files containing secrets (.env, credentials.json, etc.)
- Do not push to remote repositories unless explicitly requested by the user
- Do not use the todo_write or task tools

Commit instructions: Run git status, git diff, git log in parallel to understand changes and commit style, draft a concise message, then add and commit, and finally verify with git status. If there are no changes, do not create an empty commit.

Creating PRs: Use the gh command. Understand branch status, create a branch if needed, push, and execute gh pr create. Return the PR URL when done.
