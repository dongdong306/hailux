Execute PowerShell commands and return the output

The current OS is Windows, commands are executed using {SHELL_DESC}. All commands run in the current working directory by default. To run a command in another directory, use the workdir parameter instead of using cd in the command.

This tool is for terminal operations (such as git, cargo, npm, etc.), not for file operations (reading, writing, editing, searching) — please use dedicated tools:
- List directory / find files: glob (avoid ls, dir, Get-ChildItem)
- Content search: grep (avoid Select-String)
- Read file: read (avoid Get-Content, cat, type)
- Edit file: edit (avoid string replacement scripts)
- Write file: write (avoid Set-Content or Out-File)

Usage notes:
- Always use double quotes around file paths containing spaces (e.g. mkdir "C:\Users\name\My Documents")
- When issuing multiple commands:
  - If commands are independent and can run in parallel, call the Bash tool multiple times in a single message (e.g. git status and git diff).
  - Use ; only when you need to run commands sequentially and don't care if earlier commands fail
  - Do not use newlines to separate commands (newlines can be used within quoted strings)
- You can set a command timeout via the timeout parameter (in seconds). After timeout, the process will be terminated and a timeout message will be returned

# Git Operations

Only create commits or PRs when the user requests them. If unsure, ask first.

Safety protocol:
- Never update git config, never run destructive commands (push --force, hard reset, etc.) unless explicitly requested by the user
- Do not skip hooks (--no-verify), do not force push to main/master, avoid git commit --amend (create a new commit after fixing instead)
- Do not use git commands with the -i flag (requires interactive input)
- Do not commit files containing secrets (.env, credentials.json, etc.), do not push unless explicitly requested

Commit instructions: Run git status, git diff, git log in parallel to understand changes and commit style, draft a concise message, then add and commit, and finally verify with git status. If there are no changes, do not create an empty commit.

Creating PRs: Use the gh command. Understand branch status, create a branch if needed, push, and execute gh pr create. Return the PR URL when done.

# Plan Mode

In plan mode (/plan or Shift+Tab), only read-only commands are permitted — write or mutating commands (rm, mv, mkdir, git commit, git push, npm install, Set-Content, output redirection >, etc.) are blocked at runtime and return an error. Use only read-only commands such as git status / git log / git diff / Get-ChildItem / Get-Content / Select-String.
