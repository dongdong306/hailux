
Start a subagent to handle complex, multi-step tasks.

When using the task tool, you must specify the `subagent` parameter to select the subagent type. Available subagent types are listed in the system prompt's `<available_subagents>` block.

## When NOT to use the task tool
- If you only need to read or search files (read, glob, grep), use those tools directly
- If there is no suitable subagent, use other tools directly

## Usage Notes
1. Launch multiple subagents in parallel to maximize performance; use multiple tool calls in a single message
2. The subagent returns a message and task_id when completed. The result is not visible to the user; you need to briefly summarize the result for the user
3. Each subagent invocation uses a fresh context. Your prompt should contain a detailed task description, clearly specify what information you expect the subagent to return, and whether you expect it to write code or only do research — the subagent does not know the user's intent
4. If the subagent description mentions it should be used proactively, use it proactively without waiting for explicit user request
