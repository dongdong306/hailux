# AGENTS.md

Instructions for the `hailux` repository, injected into every coding session's system prompt.
Note: hailux itself loads `AGENTS.md` (case-insensitive) from `~/.hailux/` (global) and
ancestor dirs of the work dir — running hailux inside this repo picks up this very file
(work-dir file has highest priority).

## Commit Convention

- All commit messages **must be in English**.
- Follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `ci:`, etc.

## Comment Convention

- Write all comments in English.
- Avoid unnecessary comments — don't explain how code works; good, self-explanatory code should replace comments.
- No excuse comments for bad code — refactor the code instead of leaving a comment apologizing for it.
- Delete outdated comments promptly — a stale comment is worse than no comment.
- Add real comments only for core decisions — the "why" behind non-obvious trade-offs, workarounds, and constraints.

```sh

cargo run            # launch the TUI app
cargo run -- --web   # launch the Web UI (default 127.0.0.1:18080)
cargo test           # inline #[cfg(test)] modules across src/* + tests/integration.rs
cargo test --lib     # unit tests only (faster inner loop)

# Web frontend (required when feature "web" is on; Node 22 in CI)
cd web && npm install && npm run build   # = tsc -b && vite build → web/dist (rust-embed)

```

  still build the frontend manually after touching `web/src`.
- CI (`.github/workflows/ci.yml`): frontend build → fmt check → clippy → test → build, on Ubuntu + Windows.
- Release via release-please (`.release-please-manifest.json`); `scripts/generate-changelog.sh` feeds it.

## What hailux Is

A terminal-based AI coding assistant (like OpenCode/Claude Code) written in Rust, with an
optional Web UI. It uses `async-openai` with a **bring-your-own-transport** custom layer to
support DeepSeek-style `reasoning_content` fields. TUI: `ratatui` + `crossterm`.
Web: `axum` SSE + REST + embedded static assets (`web/`, React + assistant-ui + zustand + vite).
Features streaming chat, tool calling, MCP protocol, progressive skill system,
subagent delegation, and custom slash commands.

## Architecture (src/)

- `lib.rs` — Library entry: module declarations + startup orchestration (`run_tui`,
  `run_non_interactive`, `rebuild_database`; `run_web` lives in `web/mod.rs`). `main.rs` is
  a thin clap CLI; `tests/integration.rs` exercises the library API (permission modes,
  path resolution), not the binary.
- CLI surface: subcommands `run` (non-interactive, `--model`, `--no-tools`) and `web`
  (`--host`/`--port`/`--open`); global flags `-p/--path`, `-r/--resume`, `--yolo`,
  `--rebuild-db`, `--update`, `--web`.
- `session/` — **UI-agnostic session orchestration**. Layering: `tui/` + `web/`
  (presentation) → `session/` (`ChatSession` / `SessionManager`) → `agent/` + domain layers.
  TUI mode has a single session entry and does NOT use `SessionManager` at all (`run_tui`
  builds the Agent/App directly). Web mode keeps one `ChatSession` instance **per
  session_id** (registry keyed by session_id, lazy-built on first use: discovery + bind
  + context rebuild at creation; instances from the same work_dir have independent locks
  so multiple sessions run in parallel). Storage / Config / MCP connections are global;
  skills / subagents / commands / system prompt are discovered per work_dir. Interrupt is
  precise: per-instance `AtomicBool` cancel flag targeted by session_id
  (`SessionManager::interrupt_session`); the flag resets at each `chat_stream` start, so
  stray interrupts on idle instances are harmless.
- `web/` — Web backend (feature `web`): `handlers/` (REST routes under `/api/*`,
  `mod.rs::api_router()` + per-domain submodules: sessions/permissions/models/skills/mcp/misc),
  `sse.rs` (chat/compact endpoints + `GET /api/sessions/{id}/events` subscription),
  `runner.rs` (**background task that owns the agent event loop** — runs are spawned by the
  chat/compact handlers and keep executing after any SSE disconnect; persistence,
  auto-compaction, interrupt repair, and permission/ask registration live here),
  `bus.rs` (**SessionBus / BusRegistry** — per-session event fanout: monotonic seq,
  run-scoped replay buffer, broadcast channel, `durable_seq` watermark making DB history
  and replay complementary, `epoch` (server start timestamp) invalidating cursors across
  restarts, CAS run-claim slot enforcing single run per session),
  `protocol.rs` — **the frontend JSON contract**
  (`ServerEvent` with `#[serde(tag = "type")]`, incl. `Snapshot` first frame and
  `RunComplete` sentinel; SSE data frames carry an `Envelope { seq, event }`) mirrored by
  `web/src/runtime/types.ts`; change both together. `task_registry.rs` tracks pending
  permission/ask requests by session (they survive disconnects — no auto-deny on
  connection loss; `cancel_session` sweeps at run end); `state.rs` holds
  `WebServerState` (SessionManager + request registry + BusRegistry + epoch +
  global run-permit semaphore + default work dir + config write lock).
  Disconnect semantics: **SSE loss never interrupts a task** — the only interrupt entry
  is `POST /api/interrupt` (requires session_id). Same session: second run → 409.
  Mid-run interjection: `POST /api/interject` (409 = no active run) buffers into a
  per-run `InterjectSlot` channel (bounded, `INTERJECT_QUEUE_LIMIT` = 10 pending),
  delivered without the session lock; the agent injects at loop boundaries.
  Contract: `CoreEvent::UserMessage` echoes an injected interjection (persist →
  publish → advance_durable); `CoreEvent::InterjectDropped` reports one accepted
  but never injected (transient like `Error` — no DB row, no watermark advance;
  clients re-queue the item). `client_id` is the echo key end to end (queue item id
  ↔ optimistic bubble marker); repeats are deduped at the injection point and
  reported as dropped. Queues are in-memory per surface (TUI session / browser
  tab) — exit or switch drops them silently.
  Global concurrency cap: `[session] max_concurrent_runs` (default 4, 0 = unlimited) → 429.
  Static assets embedded from `web/dist` via rust-embed, SPA fallback to index.html;
  index.html is `no-cache`, hashed assets immutable.
- `agent/` — Core LLM interaction loop.
  - `agent/` — the agent core, split by data flow:
    `mod.rs` (Agent struct, compaction), `stream.rs` (streaming chat loop, plan-mode,
    cancellation, `AgentStreamState`), `dispatch.rs` (tool-call dispatch + permissions),
    `messages.rs` (pure message construction/sanitizing).
    Context compaction: `apply_compaction()` swaps the message list for a summary message;
    `request_compaction()` drives it from the TUI on a cloned list (not stored directly).
  - `models.rs` — **DeepSeek-compatible message types**. `CompatibleChatCompletionRequestMessage`
    wraps standard async-openai types and adds `reasoning_content` to Assistant messages.
    Custom `Serialize` injects `thinking` config and `extra` fields into the request JSON.
    Requests go through async-openai's `create_stream_byot` (BYOT = bring your own
    transport, called from `agent/stream.rs`). Messages are stored as
    `SharedMessage = Arc<CompatibleChatCompletionRequestMessage>`:
    cloning a message list is O(n) pointer copies; reminder injection (plan-mode
    prompt / exit / failure) mutates only the modified message via `Arc::make_mut`.
  - `tools/` — per-tool modules (`shell.rs`, `read.rs`, `edit.rs`, `write.rs`, `grep.rs`,
    `glob.rs`, `web_fetch.rs`, `todo.rs`, `question.rs`, plus shared `diff.rs`). `mod.rs` holds
    the `Tool` trait, `ToolRegistry` (converts tools to OpenAI function-calling schema),
    and shared path/permission helpers. `allowed_in_plan_mode()` gates write tools.
    `execute_async_with_display()` returns optional UI display data (e.g. diff hunks,
    precomputed for TUI and Web).
  - `event.rs` — `AppEvent` / `CoreEvent` definitions shared by TUI and Web backends
    (incl. `QuestionInfo`, `TaskStatus`). `CoreEvent::AskUser` carries a oneshot response channel.
  - `skill.rs` — Discovers `SKILL.md` files (YAML frontmatter `name`/`description`).
    Progressive loading: only summaries go into the system prompt; full content loaded
    via the `skill` tool.
  - `media.rs` — Image attachments as `data:<mime>;base64,<data>` URLs in memory;
    downgraded per model vision capability before sending to the provider.
  - `retry.rs` — Transient-error retry for LLM requests (network/429/5xx; config
    `[retry]` overrides defaults). Retries wrap a single request (connect + stream),
    failed attempts never enter the message context.
  - `subagent/` — **Subagent system**, split into `discovery.rs` (AGENTS.md parsing +
    directory scan), `task_tool.rs` (spec parsing + `TaskTool`), `runner.rs` (isolated
    session execution). Discovers subagent `AGENTS.md` files (frontmatter
    `name`/`description`/`tools`/`skills`/`mcp`/`model`). `TaskTool` launches subagents
    in isolated subsessions with their own tool set, skill whitelist, MCP server filter,
    and model; session resume via `task_id`; builtin `general` subagent always available.
    Isolation: own event channel — only the final text result returns to the main agent,
    tool-call progress forwarded to the main UI (truncated to 2000 chars); `question` and
    `task` tools are never registered for subagents; access filtered by frontmatter.
  - `command_def.rs` — Custom slash commands: `.md` files (frontmatter `description`).
    `CommandRegistry` unifies builtin and custom prompt commands; priority:
    project > global > builtin.
  - `agents_md.rs` — Discovers `AGENTS.md` files for system-prompt injection (paths and
    priority described in the note at the top of this file).
  - `utils.rs` — `compare_mtime`, `split_frontmatter` / `strip_frontmatter_value`
    (frontmatter parsing shared by skill / subagent / command_def).
- `prompts/` — System prompt and tool description templates (all `include_str!`).
  `mod.rs::build_system_prompt()` assembles: base prompt + working directory + skills
  summary + AGENTS.md instructions + subagents summary — session and web layers both go
  through it, never hand-assemble prompts elsewhere. `system.txt` is English.
  `tools/shell_windows.txt` vs `shell_unix.txt` selected via `cfg`.
- `permission/` — Permission engine: rules (`mod.rs::default_rules()`), `shell_arity.rs`
  (command-arity parsing for file-path detection), `shell_readonly.rs` (plan-mode shell gate).
- `config/` — Model/provider config in `~/.hailux/config.toml`, split into `mod.rs`
  (Config + load/resolve), `providers.rs` (built-in provider table: id / name / base_url /
  `native_reasoning` only — **no hardcoded models**), `types.rs` (TOML structs),
  `toml_serde.rs` (serialization + atomic save), `model_discovery.rs`
  (fetch `GET {base_url}/models`, cache in `~/.hailux/models.json`; manual refresh only —
  `R` in the TUI model picker or `POST /api/models/discover` on the web, both through the
  shared `model_discovery::fetch_provider_models`; the web endpoint also fetches with
  unsaved credentials for the add-model flows). The visible model list is exactly
  the provider's model table: `/models` results are only a hint layer (cached in
  `~/.hailux/models.json`) feeding the fetch dialogs — TUI (R key in the picker, and the
  setup flow after the API key) and web (`POST /api/models/discover` + checkbox dialog) let
  the user tick models, and `POST /api/models/apply-discovered` / `Config::apply_discovered_models`
  materialize the picked rows with the reported metadata; already-present rows win and the
  main model is never switched by a fetch. `resolve()` is table-driven only — an unlisted
  model cannot be used.
  Built-in providers: `deepseek`, `zhipu-coding-plan` (endpoint + `thinking` switch only);
  custom supported. Selector format `provider/model`. `resolve()` returns `ResolvedModel`.
  Also holds `compact_threshold`, `[retry]` (transient-error retry tuning),
  `reasoning_effort`, and `[session]` (`max_concurrent_runs` — web global run cap).
- `mcp/` — MCP client via `rmcp`: `config.rs` reads `~/.hailux/mcp.toml` (stdio + http
  transports, auto-generates commented sample); `client.rs` connects in background and
  registers tools. `SharedMcpBackends` shared with `TaskTool` for subagent MCP access.
- `storage/db/` — SQLite chat history at `~/.hailux/db/chat.db`, split by data domain:
  `mod.rs` (ChatStorage, migrations, rebuild), `models.rs` (DTOs), `sessions.rs` /
  `messages.rs` / `usage.rs` (CRUD per domain), `convert.rs` (OpenAI ↔ storage mapping).
  **Versioned migrations
  via `sqlx::migrate!`** (`migrations/*.sql`): new schema change = new migration file, no
  hand-written fallbacks. File DB runs **WAL** journal mode, pool = 8 (parallel web
  sessions read concurrently; writes serialize via busy_timeout 5s) — `backup_db_file`
  snapshots via `VACUUM INTO` (WAL-aware consistent snapshot) with a
  checkpoint+copy fallback. In-memory test pools stay `max_connections(1)` (`:memory:` is
  per-connection).
  Supports subsessions
  (parent/child for subagent isolation). `messages.compacted` + `sessions.compact_summary`
  support context compaction; active-context queries filter `compacted = 0`. Migration
  failure aborts startup and suggests `--rebuild-db`.
- `updater.rs` — Self-update from GitHub releases (sha256-verified asset download when a
  `.sha256` asset exists — otherwise verification is skipped with a warning; Windows swaps
  via a `.old` file cleaned up on next startup).
- `share/` — Session export as a self-contained single-file HTML (TUI `/share` command +
  `GET /api/sessions/{id}/export`); XSS-escaped, CSS/images inlined, styling aligned with
  the Web chat UI.
- `tui/` — Ratatui UI. `app/` is a directory: `mod.rs` (main event loop / state machine),
  `chat_events.rs` (CoreEvent handling), `chat_input.rs` (+ `paste.rs` — the PasteBurst
  state machine, `attachments.rs` — image attach helpers), `session_ops.rs`, `app_render.rs`,
  `overlay/` (model/effort/setup/skills/stats/mcp/tasks overlay events, dispatched from
  `overlay/mod.rs`; the model picker's `R` key refreshes a provider's `/models` list via a
  background task that reports back as `AppEvent::ModelsRefreshed`), `types.rs` (`AppState`).
  `ask_user.rs`
  (question dialog + `ask_escape`), `history_cell/`
  (history rendering units by cell type: message/tool/task/todo/diff/`ask_user_render.rs`
  — incl. `parse_ask_user_pairs`), `event.rs` (async event channel),
  `input.rs` (paste detection — PasteBurst is a complex timing-based state machine, be
  careful when modifying input handling), `command.rs` (slash commands), `terminal.rs`
  (init/restore + panic hook); other files render panels (pickers, viewers, setup,
  markdown).
- `web/` (frontend dir at repo root) — React 19 + assistant-ui + zustand + Tailwind 4 +
  vite. `src/runtime/hailux-runtime.tsx` bridges SSE events into assistant-ui message parts;
  `src/store/` holds app state (`app-store.ts` main store — chat/compact are **submit-only**
  POSTs, run events always arrive via the subscription, `types.ts` state contract,
  `stream-manager.ts` — **single-stream ownership** (generation-token guarded; exactly one
  subscription app-wide, stale continuations inert by construction),
  `run-sink.ts` — the envelope decoder + per-session event router
  (Snapshot/seq dedupe; events only mutate `items` when their session is the
  current view, so switching away never loses or duplicates a running task),
  `shared-events.ts` event helpers, `session-history.ts` pure history rebuild);
  `src/components/` renders UI (sidebar shows a pulsing dot for sessions with active runs).

## Key Quirks

- **Platform**: Primarily developed on Windows. `ShellTool` prefers `pwsh.exe` (PowerShell 7+)
  on Windows, falling back to `powershell.exe` (5.1); and `bash -c` on Unix; the `workdir`
  parameter only exists on non-Windows. Windows commands are wrapped with a UTF-8 prologue
  (`WINDOWS_UTF8_PROLOGUE` in `agent/tools/shell.rs`) to force UTF-8 on both pipe directions.
  Windows adds a `crossterm_winapi` dependency and different paste-detection timing constants.
  The Windows shell is spawned with `CREATE_NO_WINDOW` (own hidden console) and
  `stdin(null)`: GUI-subsystem grandchildren (e.g. headless Edge/Chrome) would otherwise
  `AttachConsole(ATTACH_PARENT_PROCESS)` and scribble the TUI's alternate screen directly
  (ratatui diff-rendering never repairs those cells). Side effect: PowerShell table output
  formats to the hidden console's default width (~120 cols), and console resize from within
  commands is unreliable — don't "fix" either. After a shell tool run, TUI forces a full
  repaint (`render.force_clear`) as belt-and-braces.
- **Web is loopback-only by default** (`127.0.0.1`). Work-dir selection means the server can
  read any local directory — exposing `0.0.0.0` is an explicit trust decision (documented in `web/mod.rs`).
- **Web run lifecycle is decoupled from SSE** (`web/runner.rs` + `web/bus.rs`): a run is a
  spawned task; SSE connections are replaceable observers. Protocol invariants: every
  event has a per-session monotonic `seq` (survives across runs; `durable_seq` watermark =
  `head_seq` in `GET /api/sessions/{id}` marks what DB history already covers, replay =
  buffered events with `seq > since`); `epoch` (server start) must match or the client
  must discard cursors and rebuild from history; runs end with a `RunComplete` sentinel
  (POST observer streams close on it; `GET /api/sessions/{id}/events` subscriptions stay
  open across runs for idle→live transitions). Pending permission/ask requests live for
  the run, not the connection — a closed tab no longer auto-denies; replays re-surface the
  dialog; reply endpoints return 410 Gone once consumed. Model/plan/effort broadcasts use
  `try_lock` and skip locked instances — the chat entry re-syncs modes AND model
  (`ChatSession::current_model_display` vs `manager.resolved()`) at every request start.
- **question reply contract** (5 implementations must stay in lockstep): TUI submits
  `"question"="answer"` pairs, comma-joined, with `\` and `"` escaped
  (`tui/ask_user.rs::ask_escape`; formatting lives in `tui/ask_user.rs::format_ask_reply`);
  parsed back by
  `tui/history_cell/ask_user_render.rs::parse_ask_user_pairs`;
  Web mirrors both (`web/src/components/dialogs.tsx::formatAskReply` and
  `web/src/components/assistant-ui/tool-fallback.tsx::parseAskUserPairs`);
  `share/mod.rs::parse_ask_user_pairs` re-parses for HTML export rendering. Magic strings:
  `"[User Cancelled]"` (sent as fallback by `tui/ask_user.rs` and `web/task_registry.rs`,
  checked in `agent/tools/question.rs`), `"Unanswered"` (default in `tui/ask_user.rs`, rendered
  by `tui/history_cell/ask_user_render.rs`), and `"[Custom input] "` (prefix marking free-text
  answers; constant in `agent/event.rs::CUSTOM_ANSWER_PREFIX`, membership rule in
  `agent/event.rs::is_custom_answer`, mirrored by web `dialogs.tsx::isCustomAnswer`,
  explained to the model by `agent/tools/question.rs`). A single question also routes through the Confirm tab — no
  auto-submit on selection (TUI and Web aligned).
- **Question panel takes over the input slot** (not a modal): while a question is
  pending the history above stays scrollable. TUI: `ChatWidget.input_hidden` leaves
  the input slot blank and `RenderResult.input_area` hands its rect to
  `ask_user::render_ask_user_panel`; the height is content-driven
  (`ask_user_panel_height`, measured and rendered by the same `build_ask_user_lines`)
  and clamped to 60% / `height-6` in `app_render.rs`, with keep-selected-visible
  windowing (`window_ask_user_lines`) when clamped; wheel / PgUp / PgDn scroll the
  history via `App::scroll_chat` (shared with the chat keys), arrows keep selecting
  options, and only the panel's own custom-input cursor is shown. Web mirrors the
  TUI's tab model (one question per tab, picking advances, Confirm tab reviews):
  `AskUserPanel` renders in the composer slot while `ChatInput hidden` stays
  mounted (its draft is local state — never unmount it); Esc inside a text input
  only leaves editing, elsewhere it cancels.
- **Permission defaults**: In-workdir operations allowed by default via builtin lowest-priority
  rules in `permission/mod.rs::default_rules()`: `* allow`, `external_directory * ask`,
  `read *.env` / `*.env.* ask` (`.env.example allow`), `mcp * ask`. Grep aligns with the env
  gate: directory searches skip env-type files (skip note appended to output), and a `path`
  pointing directly at one appends a `read` request (`permission::is_env_gated_file_name`).
  Tools issue
  `external_directory` requests when a path resolves outside the workdir — read/edit/write/
  grep/glob path args plus the shell `workdir` param. `[permission.xxx]` config rules
  (session > config > builtin defaults) override the defaults; `read` in-workdir requests use
  absolute-path patterns so `.env` rules match via `wildcard_match` — a `\`→`/`-normalized,
  Windows case-insensitive, `*`/`?`-wildcard matcher with literal special chars.
  `Tool::extract_permission` returns an **ordered** `Vec<PermissionRequest>`: shell puts its
  command-rule request first, external-directory second, so `[permission.shell] "rm *"="deny"`
  short-circuits before the out-of-workdir ask
  (`agent/agent/dispatch.rs::evaluate_permission_requests`
   evaluates in order; Deny short-circuits, first Ask dialogs, `Once` only covers that one
   request). Session "always" rules persist under the **request's** permission category, not the
   tool category.
- **Shell static analysis** (`permission/shell_scan.rs`): best-effort gating, NOT a sandbox —
  documented in tool prompts and help skill. Splits sub-commands on top-level `&&`/`;`/`|`/`&`
  (quote-aware; escape model follows the platform shell like `ShellTool` does — backslash on
  Unix, backtick-only on Windows, so a PowerShell path ending in `\` does not fuse commands);
  classifies first tokens as FileOps (`cat`, `rm`, `ln`, `tee`, ... — all
  args scanned as path candidates) / Executor (`sudo`, `sh`, `python`, `eval`, `xargs`, ... —
  sets `force_ask` on the shell request so builtin `* allow` doesn't waive it; only explicit
  session/config rules do) / Other (redirection targets still checked). `cd X` tracks a
  per-command resolution base (updated per segment) instead of gating cd itself: the hit
  lands on the segment that actually touches files, so `cd .. && ls` is silent while
  `cd .. && cat secret` asks for the real target dir. Known vars
  (`$HOME`/`$env:NAME`) and script-assigned variables (`$n = "literal"`, tracked per
  command, case-insensitive) are expanded; unknown `$var`/`$(...)`/backticks are skipped (documented
  best-effort trade-off); `~` expands; globs resolve by their path prefix so `../x/*.pem` is
  gated while in-workdir globs pass.
- **Plan mode** (`/plan` or Shift+Tab): filters out write/edit tools from the tool list and
  appends a read-only system-reminder to each user message entering while plan mode is on
  (persistent context, persisted via `PersistUserReminder` so rebuilds splice it back);
  the first message after leaving plan mode carries an exit reminder that countermands
  the historical ones (`agent/agent/mod.rs::chat_stream`, tracked by `plan_context`,
  restored from the last *active* (non-compacted) user row's `runtime_meta.plan_mode` on
  session rebuild via `storage::stored_plan_mode` — compaction wipes the rows carrying
  the reminders from the rebuilt context, so nothing needs countermanding after it).
  `shell` stays available but is hard-gated by `permission/shell_readonly.rs::is_read_only_shell_command`
  (fail-closed allowlist: git read subcommands, ls/cat/grep, PowerShell Get-* cmdlets; redirects
  `>`/`>>` and unknown commands are denied) — rejected in the agent permission check without a dialog.
- **CRLF handling**: `EditTool` normalizes line endings to match the file's style before
  string matching, so LLM-provided `\n` works on `\r\n` files. `.gitattributes` forces LF
  for `*.rs`/`*.sql`/`*.json`/`*.toml` (migration checksum safety); web `*.tsx/*.ts` fall
  under `core.autocrlf` — don't "fix" line endings manually.
- **Context compaction**: `/compact` or auto-trigger when usage crosses `compact_threshold`
  (config.toml) × max context tokens. Compaction marks messages `compacted=1` in SQLite
  (never deletes rows), stores the summary in `sessions.compact_summary`, renders a
  "Context compacted" marker.
- **Message sync**: after streaming completes, `Agent::sync_messages()` replaces the
  in-memory message list with the final streamed messages (which include tool results).
- **No clippy lints configured** — `#[allow(dead_code)]` is used liberally on builder methods.
